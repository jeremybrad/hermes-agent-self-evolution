## [0.1.0] — 2026-04-24

### Added (from upstream + this fork)
- DSPy + GEPA evolution pipeline (Phase 1 proof-of-concept).
- Hermes session importer + short skill-name matching.

### Fixed (the 2026-04-24 cascade)
- GEPA constructor: `max_steps` → `max_full_evals` + `reflection_lm`
  (dspy 3.2 API).
- GEPA metric: variadic-tolerant — accepts the 5-arg form GEPA calls AND
  the 3-arg form MIPROv2/BootstrapFewShot use.
- Constraint validator: now called with frontmatter-bearing skill text.
- Skill text becomes the actual optimization target — embedded as
  `predictor.signature.instructions` rather than a runtime input field
  (so GEPA's mutations actually reach the saved artifact).
- Evolved-instructions extraction uses `named_predictors()` for
  dspy 3.2's wrapped `ChainOfThought`.

### Validated
- One honest run on the `arxiv` skill: baseline 0.395 → evolved 0.410
  (+3.9% on keyword-overlap proxy), body 9773→2430 chars (-75%).
  See `70_evidence/runs/arxiv/20260424_184914/` after the layout
  migration (was `output/arxiv/20260424_184914/` pre-migration).

### Known limitations carried into 0.2
- Fitness function is keyword overlap, not the LLM-as-judge that
  exists in code but isn't wired into a run yet.
- Eval set is 15 synthetic examples, all generated by gpt-4o-mini from
  the skill text itself.
- Generalization is single-skill (`arxiv`).
- Constraint suite is shallow (size, growth, structure, non-emptiness).
- `optuna` dependency is uncommitted to `pyproject.toml`.
